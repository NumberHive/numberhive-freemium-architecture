Number Hive Development Roadmap

Five phases from MVP to platform maturity — each phase builds on the last, unlocking the next level of the product.
Development Timeline
Five sequential phases. Each phase delivers a usable product increment and creates the foundation for the next. No phase can be skipped — they build on each other.

Build Dependencies

Phase 1 → Game engine, AI opponent, and core UI must exist before anything else
Phase 2 → Hive system and student accounts required before paid features
Phase 3 → Payment infrastructure and reporting engine needed for school tier
Phase 4 → Multi-educator architecture required before platform-scale features

What Each Phase Unlocks

Phase 1 → First users, gameplay validation, public acquisition funnel
Phase 2 → B2B value proposition, teacher adoption, silent data collection
Phase 3 → First revenue, data-driven upgrade triggers, conversion validation
Phase 4 → Institutional sales, district pipeline, school-level adoption
Sequential
Each phase must be complete before the next begins. No skipping — the foundations compound.
Shippable
Every phase produces a working product. Users get value at each stage, not just at the end.
Validated
Each phase has success criteria. Move forward only when the current phase proves its thesis.
Compounding
Later phases get easier. Network effects, data, and user base built in earlier phases accelerate everything after.
Roadmap Philosophy
Ship the public game first. Prove the magic moment. Add the educator layer. Prove conversion. Then scale — classroom, school, platform. Each phase earns the right to build the next.
🎮

Phase 1 — MVP Public Game

Get the game live. Prove that anonymous visitors will play, engage, and return. This is the foundation everything else is built on.
🚀
No prerequisites. This is the starting point. Build the core game engine, deploy it publicly, and validate that people want to play Number Hive.
Key Deliverables
🧠
Core Game Engine
Number Hive gameplay mechanics — board, rules, move validation, win conditions
🤖
Basic AI Opponent
Single-player mode against a standard-difficulty bot — the default experience for anonymous users
🖥
Responsive Game UI
Desktop and mobile-optimised interface. Clean, fast, works on school devices
👤
Anonymous Play Mode
Zero-friction entry — no account, no email, no sign-up. Land on the page, play immediately
🌐
Public Landing Page
Marketing page with clear CTA to play. SEO-ready. Explains the game in under 10 seconds
📊
Basic Analytics Infrastructure
Track sessions, games played, time on site, return visits. Foundation for all future data
Milestones
◆
Game playable end-to-end
A complete game can be started, played, and finished against the AI
◆
Public deployment live
Game accessible at a public URL — anyone can play without authentication
◆
Magic moment validated
Evidence that players complete games and return — the core engagement thesis holds
◆
Mobile experience confirmed
Game performs well on tablets and phones — critical for classroom use in Phase 2
Success Criteria
How we know Phase 1 is complete and we can move to Phase 2.
✓
Players complete full games against AIgame completion rate > 60%
✓
Return visitors without registrationday-7 return rate tracked
✓
Works on school-standard devicesiPad, Chromebook, Android tablet
✓
Sub-3s load time on standard connectionsLCP < 3000ms
🎓

Phase 2 — MVP Educator

Add the educator layer. Free teacher accounts, single hive management, student join flow. Prove that teachers adopt and students engage in a classroom context.
⬅
Requires Phase 1. The core game engine and public play must be live and validated before adding the educator layer on top.
Key Deliverables
🔐
Educator Registration & Authentication
Free teacher sign-up flow — email, password, basic profile. No payment required
🐝
Hive Creation & Management
Teachers create a single hive (free tier limit), set a hive code, manage their class
👧
Student Join Flow
Students enter name + hive code to join — no email, no account creation, immediate access
🎯
In-Hive Gameplay
Students play vs other students and vs basic AI within the hive context
📝
Silent Data Collection
Gameplay data captured and stored — fluency metrics, response times, skill gaps. Not yet visible to teachers
🌉
Teacher Transfer Bridge
Public game players who are teachers see "Bring this to your class" CTA — transfer into educator experience
📋
Educator Dashboard (Basic)
Teacher sees their hive, student list, active sessions. No analytics yet — just management
Milestones
◆
First teacher creates a hive
End-to-end flow works: sign up → create hive → share code → students join
◆
Classroom session completed
A real class of students plays a full session within a hive with teacher oversight
◆
Data pipeline operational
Gameplay data flows into storage — verified by querying collected metrics for a test hive
◆
Transfer bridge active
At least one public player converts to educator via the bridge CTA
◆
Teacher re-engagement
Teachers return and run multiple sessions — the product sticks beyond the first try
Success Criteria
How we know Phase 2 is complete and we can move to Phase 3.
✓
Teachers create hives and run sessionshive activation rate tracked
✓
Students join with name + code in under 60sjoin-to-play < 60s
✓
Data collection verified end-to-endall gameplay events captured
✓
Teachers return for a second sessionweek-2 retention tracked

Phase 3 — Classroom Tier

Introduce paid subscriptions. Multiple hives, intra-hive competency reporting, classroom tools. This is where Number Hive begins generating revenue.
⬅
Requires Phase 2. The free educator tier must be validated — teachers using hives, data collecting silently — before layering on paid features and reporting.
Key Deliverables
💳
Subscription & Payment System
Stripe integration, plan management, billing portal. Per-educator pricing (term or annual)
🐝
Multiple Hive Support
Classroom subscribers create hives for different classes, year groups, or ability sets
📊
Competency Reporting Engine
Unlock the silently-collected data — fluency profiles, growth trends, skill gap analysis per hive
🔥
Heat Maps
Visual class-wide competency heat maps — which skills are strong, which need intervention
🎯
Skill Assignment
Teachers assign specific skills to struggling students — analytics with consequence
🔒
Hive Vault UX
Free-tier teachers see blurred data, locked reports, "14 profiles waiting" — the conversion pressure layer
📤
Report Export
Download class reports as PDF or CSV — teachers share with parents, coordinators, admin
🏆
Competitions & Challenges
Teachers run structured competitions within and between their hives
Milestones
◆
First paid subscription
A real teacher converts from free to classroom tier — revenue begins
◆
Reporting engine validated
Teachers use reports to make instructional decisions — the data-to-action loop closes
◆
Hive Vault conversion measured
Free → paid conversion rate established — does the locked-data model drive subscriptions?
◆
Multi-hive adoption
Paid teachers create 2+ hives — the multi-class use case is real
◆
Teacher-to-teacher referral
At least one organic referral — a teacher invites a colleague to Number Hive
Success Criteria
How we know Phase 3 is complete and we can move to Phase 4.
✓
Free → Classroom conversion provenconversion rate > 5%
✓
Teachers use reports for instructionreport views per session tracked
✓
Payment flow zero-frictioncheckout completion > 80%
✓
Organic referrals occurringteacher invites tracked

Phase 4 — School Tier

Institutional deployment. School-wide licences, sub-educator management, inter-hive reporting, and the infrastructure for district-level sales.
⬅
Requires Phase 3. Payment infrastructure, reporting engine, and multi-hive architecture must be proven before building school-level administration and multi-educator systems.
Key Deliverables
🏢
School Account & Licence Model
School-wide subscription — single billing, covers all educators. Volume pricing structure
👥
Sub-Educator Management
School admin adds and manages multiple teachers. Each teacher manages their own hives under the school umbrella
📊
Inter-Hive Competency Reporting
Compare performance across hives, classes, year groups. School-wide view of competency data
🛡
School Admin Dashboard
School coordinator sees all hives, all educators, all students. Oversight without micro-management
📈
Cohort Tracking
Track student progress across years and hives — longitudinal data for school improvement planning
🔗
SSO / Rostering Integration Prep
Architecture for future SSO (Google, Microsoft, Clever) and student rostering integration
📄
Enterprise Sales Collateral
Case studies from Phase 3 teachers, ROI documentation, deployment guides for school coordinators
Milestones
◆
First school licence sold
A school signs up with 3+ educators under a single school account
◆
Multi-educator workflow validated
Sub-educators independently manage hives while school admin has oversight
◆
Inter-hive reporting used
School coordinator uses cross-class reports for school improvement decisions
◆
Classroom → School upgrade
A school with multiple individual Classroom subscriptions consolidates to a School licence
◆
District conversation started
At least one district-level conversation initiated based on school success stories
Success Criteria
How we know Phase 4 is complete and we can move to Phase 5.
✓
School accounts with 3+ educatorsmulti-educator adoption proven
✓
Cross-class reporting drives decisionsadmin report usage tracked
✓

✓

Phase 5 — Platform Maturity

Network effects, Hive Clash, viral growth loops, and district-level scale. The platform becomes self-reinforcing — users acquire users.
⬅
Requires Phase 4. School-level infrastructure, proven revenue model, and established user base needed before investing in viral mechanics and platform-scale features.
Key Deliverables
⚡
Hive Clash — Hive IQ
Global ranking system. One ladder, every player, everywhere. Students compete across schools and the public game
🏅
Global Leaderboard & School Rankings
Public leaderboards, school-level rankings, regional comparisons. Social currency for students
🔗
Challenge Links & Viral Sharing
Students share challenge links outside school. Friends play immediately — zero-friction viral loop
🏟
Seasons & Tournaments
Time-limited competitive seasons. School and district tournaments with rankings reset periodically
🔑
Player Registration (Public)
Full registered player experience — vs local, vs remote, vs advanced AI, persistent progress record
🏢
District Licensing & SSO
District-level contracts with sub-$1/student pricing. SSO via Google, Microsoft, Clever
📱
Dedicated Mobile Experience
Native or PWA experience optimised for student home use — push notifications for challenges
🔄
B2C → B2B Acquisition Loop
Track and optimise the path from public player to teacher to subscriber. The product acquires its own customers
Milestones
◆
Hive IQ launched publicly
Global ranking system live — students across schools and public game on one ladder
◆
Viral loop measurable
Challenge links generating new users — tracked from share to sign-up to play
◆
Home play established
Significant number of students playing outside school hours voluntarily
◆
First district deal
A district-level contract signed — multiple schools under one agreement
◆
B2C-to-teacher conversion proven
Measurable number of teachers discovered Number Hive as public players first
◆
Self-sustaining growth
New user acquisition from network effects exceeds paid acquisition — the flywheel turns on its own
Success Criteria
The platform maturity thesis is validated when these conditions hold.
✓
Students play at home without being askedout-of-school sessions > 30%
✓
Challenge links generate new usersviral coefficient > 0.3
✓
B2C players become educatorspublic → educator conversion tracked
✓
District-level adoption pipelineactive district conversations > 3
The Endgame
Number Hive becomes a self-reinforcing platform. Students play because they want to. Teachers adopt because students are engaged. Schools subscribe because teachers prove value. The product acquires its own customers.
